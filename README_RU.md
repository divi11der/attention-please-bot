# Attention Please! — бесплатный Telegram-бот через Render Web Service

**Что внутри:**

- `bot.py` — работает через **Telegram webhook**, слушает HTTP-порт Render.
- `requirements.txt` и `.python-version` — Python 3.12 + aiogram + asyncpg.
- `render.yaml` — необязательный шаблон Render Blueprint (также можно создать Web Service вручную).
- `.env.example` — образец переменных, **не** хранит рабочий токен.
- `import_old_db.py` — необязательный импорт старой локальной базы `support.db` в Neon.

## 1. Создай БЕСПЛАТНУЮ базу Neon

1. Перейди на https://console.neon.tech/ и зарегистрируйся.
2. Создай проект, например `attention-please` на тарифе **Free**.
3. Открой проект → **Connect** (иногда кнопка называется `Connection Details`).
4. Скопируй **Connection string** формата:

   `postgresql://USER:PASSWORD@ep-xxxx.REGION.aws.neon.tech/neondb?sslmode=require&channel_binding=require`

   Рекомендуется **Direct connection** (без `-pooler` в имени сервера). Код сам включает TLS и убирает дополнительные параметры URL Neon, несовместимые с asyncpg.
5. Сохрани строку для шага с переменными Render. Это **секрет** — не загружай её в GitHub и никому не присылай.

> Почему не SQLite? Бесплатный Render удаляет локальные файлы при остановке/перезапуске. В Neon данные остаются после перезапусков бота. Бесплатная база **Render Postgres**, в отличие от Neon, ограничена сроком 30 дней.

## 2. Загрузи бот на GitHub

1. Создай **Private**-репозиторий: https://github.com/new
2. Название, например: `attention-please-support`.
3. В GitHub нажми **Add file → Upload files**.
4. **Распакуй ZIP и загрузи ФАЙЛЫ ИЗ НЕГО в корень репозитория**, а не сам ZIP и не папку целиком. В корне должны лежать `bot.py`, `requirements.txt`, `.python-version`, `render.yaml`.
5. Нажми **Commit changes**. Не загружай `support.db`, `.env`, ключи и токен.

## 3. Создай Render Web Service

1. Перейди на https://dashboard.render.com/ → **New → Web Service** (НЕ Background Worker).
2. Подключи GitHub и выбери созданный репозиторий.
3. Выставь:

   | Поле | Значение |
   |---|---|
   | Name | `attention-please-support` (или любое свободное) |
   | Language / Runtime | `Python` |
   | Branch | `main` |
   | Build Command | `pip install -r requirements.txt` |
   | Start Command | `python bot.py` |
   | Instance Type | **Free**, а не Starter |

4. В **Environment** добавь:

   | Key | Value |
   |---|---|
   | `BOT_TOKEN` | секретный токен BotFather |
   | `DATABASE_URL` | полная строка подключения Neon |
   | `TEAM_CHAT_ID` | ID закрытой группы разработчиков (начинается с `-100`, значение может отличаться) |

   **`RENDER_EXTERNAL_URL` и `PORT` НЕ вводи:** Render предоставляет их автоматически. Бот сам установит webhook на `https://имя-сервиса.onrender.com/telegram/webhook`. Вебхуку не нужен внешний TLS-сертификат в коде — Render предоставляет HTTPS.

5. Нажми **Deploy Web Service**. Дождись, пока в **Logs** появится:

   - `PostgreSQL connected; support tickets are stored persistently`
   - `Telegram webhook enabled: https://.../telegram/webhook`

6. Открой ссылку `https://имя-сервиса.onrender.com/` в браузере. Если сервер проснулся, увидишь JSON `{"status":"ok","app":"Attention Please Support"}`.
7. В Telegram напиши боту `/start`, выбери категорию и отправь тестовый вопрос. Разработчик отвечает **через «Ответить» (Reply)** на заголовок или скопированное сообщение в группе.

### Если не знаешь ID группы

Сначала поставь в Render Environment `TEAM_CHAT_ID=0`, дождись Deploy. Добавь бота в **закрытую** группу разработчиков и отправь сообщение `/id@username_твоего_бота`. Бот ответит `ID этого чата: -100...`. Теперь замени `TEAM_CHAT_ID` в Render на полученное значение → **Save, deploy**, и бот начнёт пересылать обращения.

Важно: Telegram-бот должен состоять в группе. Для ответов отвечай **на сообщения, которые отправил бот**. Команда `/id` работает и без настроенного `TEAM_CHAT_ID`.

## 4. Что умеет бот

1. Игрок нажимает `/start`: **🐞 Сообщить об ошибке / 💡 Предложить идею / ❓ Задать вопрос**.
2. После выбора категории одно сообщение/фото/файл передаётся в закрытую группу разработчиков и записывается в Neon. Обращение получает номер.
3. Игрок пишет `/cancel` или нажимает **❌ Отменить обращение**:
   - если игрок ещё не отправил текст, отменяется только черновик;
   - если текст уже ушёл команде и ещё не отвечен, разработчики получают сообщение **«❌ Игрок отменил обращение»**, а ответ на отменённое обращение больше не отправится.
4. Разработчик нажимает **Ответить** на сообщение обращения в группе. Игроку приходит:

       📩 Администрация ответила на ваше сообщение!

       📝 Ваше обращение:
       Не работает кнопка Start.

       💬 Ответ администрации:
       Исправим в следующем обновлении!

5. После первого ответа обращение становится «answered», но разработчик может отправить ещё один ответ на то же сообщение. Отменять уже отвеченные обращения нельзя.
6. Старые записи не исчезают после сна и перезапуска Render: все обращения и связи с сообщениями сохраняются в **Neon**.

### Как подключить к Godot

```gdscript
func _on_contact_button_pressed() -> void:
    OS.shell_open("https://t.me/ИМЯ_ТВОЕГО_БОТА")
```

## 5. Если у тебя уже есть старый `support.db` (необязательно)

**Новая база не импортирует старую SQLite автоматически.** Но в архиве есть `import_old_db.py`. Прежде чем запускать импорт, **сделай резервную копию старого `support.db`**. После успешного первого деплоя Web Service (желательно **до приёма новых обращений**, чтобы не пересеклись номера) можно выполнить на ПК из папки с распакованными файлами:

```cmd
py -3.12 -m pip install -r requirements.txt
set "DATABASE_URL=ТВОЯ_СТРОКА_ИЗ_NEON"
py -3.12 import_old_db.py "C:\путь\к\старому\support.db"
```

Это переносит старые обращения, черновики и соответствующие связи сообщений. Файл SQLite открывается **только на чтение** и не меняется. При повторном запуске импорт не дублирует данные. Если старые ссылки на сообщения были сохранены в старом формате без номера обращения, их восстановить автоматически нельзя.

После проверки импорта закрой CMD с ключами; не делись DATABASE_URL и BOT_TOKEN.

## 6. Ограничения бесплатного варианта

- Render Free **засыпает через 15 минут без входящего HTTP-трафика**, просыпается от Telegram webhook. Пробуждение обычно около минуты, поэтому сообщения после простоя могут приходить **не сразу**; Telegram может повторно посылать обновление после неудачной доставки, но мгновенную/100%-ную доступность бесплатный тариф не гарантирует.
- Не настраивай UptimeRobot или другие постоянные пинги ради обхода сна. Для настоящего 24/7 без задержки нужен платный сервер.
- У Render и Neon есть **бесплатные квоты**, тарифы могут меняться. В Render выбирай `Free` и проверяй предупреждения о возможных списаниях.
- Для Render Free **не нужна опция Persistent Disk**. Данные хранятся в Neon, а не в файловой системе сервера.
- Запущенный локально polling-бот со старой версией должен быть **остановлен**: Telegram не позволяет одновременно использовать polling и webhook для одного токена.
- **Не удаляй базу Neon**, если нужно сохранить обращения. При желании экспортируй резервные копии отдельно.
- Новая версия требует `BOT_TOKEN`, `DATABASE_URL`, публичный адрес Render и Python 3.12. `TEAM_CHAT_ID` можно добавить после первого деплоя.

Если видишь `Deploy failed`, открой **Render → Logs**. Если работающая программа пишет `RuntimeError`, проверь переменные Environment. Если Neon не подключился, проверь правильность `DATABASE_URL` и разрешённость исходящих соединений.


## Обновление v2: исправление кнопок после сна Render

В версии v2 бот сначала безопасно подтверждает нажатие, затем записывает выбранную
категорию в Neon и **всегда пытается отправить приглашение написать обращение**.
Если подтверждение кнопки Telegram устарело во время пробуждения Render, программа
не обрывает обработку. Ошибки базы данных теперь регистрируются в Logs, а игрок
получает понятное уведомление вместо молчания. HTTP webhook подтверждается быстро,
чтобы уменьшить повторные доставки после медленной обработки.

Чтобы обновить: в GitHub открой `bot.py` → значок карандаша → замени текст
содержимым `bot.py` из нового ZIP → `Commit changes`. Render автоматически
пересоберёт сервис при включённом Auto Deploy. Если Auto Deploy выключен,
в Render выбери `Manual Deploy → Deploy latest commit`.

**Не меняй** `BOT_TOKEN`, `DATABASE_URL`, `TEAM_CHAT_ID`: всё уже сохранено в Render.
В `Logs` после деплоя должны быть строки `PostgreSQL connected` и
`Telegram webhook enabled`. Дождись статуса **Live**, затем проверь `/start`,
«Сообщить об ошибке» и отправку тестового сообщения в группу.

Примечание: бесплатный Render всё равно может просыпаться 30–60 секунд. Если
первое нажатие не обработалось, открой URL сервиса /health, дождись ответа и
нажми на кнопку ещё раз. Для мгновенной доступности всегда нужен сервер без сна.
